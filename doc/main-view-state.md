# 主视图状态与导航

## 状态边界

每个 `HiNoteView` 有一份 `ViewState`，没有全局共享的页面状态。`currentFile`、`isFlashcardMode` 等旧名称现在是派生 getter，不能直接赋值。

- `placement`：侧边栏 / 主窗口。
- `page`：无文件 / 单文件 / Canvas / 全部高亮 / HiCard。
- `search`：原始输入及统一解析的范围、类型、关键词。
- 展示状态：设备信息、窄窗格、导航展开状态。
- 请求状态：加载版本及 idle / loading / ready / error。

`FileListController.navigate` 是页面切换入口，负责失效旧请求、保留草稿、清理选择与分页、退出旧组件并打开新页面。`LayoutManager` 只更新显示，不加载文件，不触发全库扫描。窗口缩窄或展开导航不会改变当前页面。

## 行为

- 侧边栏跟随打开的文件；主窗口独立选择浏览范围。
- 当前文件修改后刷新相关内容，多个文件事件合并处理。主窗口独立选中文件不会阻止该文件内容更新。
- `all:` 和 `path:` 使用知识库范围，`comment:` 和 `hicard:` 筛选当前页面范围。搜索不临时改写当前文件。
- 在同一已加载范围内继续输入使用内存数据；显式刷新重新加载。输入变化立即让旧请求失效，不等待防抖结束。
- 不增加顶部工具栏。点击文件列表标题 **HINOTE** 刷新列表和当前内容；标题支持 Enter / Space，连续点击不会重复启动刷新。窄窗格保留原有返回入口，列表项支持键盘进入。
- HiCard 的返回先交给学习组件处理分组层级，再返回导航或全部高亮。
- 切换侧边栏 / 主窗口时传递当前会话，包括主视图选择、搜索和草稿。重复打开同一位置只激活现有视图。

## 异步保护

文件、全部高亮、Canvas、搜索和 HiCard 激活共享视图请求版本。只接受仍属于当前页面的结果，旧结果、旧错误和旧分页回调不改变新页面。HiCard 的许可证查询完成后也检查组件是否仍有效。

关闭视图会让请求失效，并清理分页观察器、搜索监听、HiCard、设备监听及评论编辑器。卡片注册表按所属容器清理，避免一个视图刷新时销毁另一个视图的卡片。

评论及晚到的 AI 回复始终按高亮自己的 `filePath` 保存；来源文件不存在时不回退到当前选中的其他笔记。删除评论完成后的回调只更新对应卡片，不再用旧的整份高亮数组覆盖当前页面。

## 草稿

切换、刷新或重建卡片前，保存已打开评论输入框的文本到当前视图内存。再次打开同一高亮 / 评论的编辑器时恢复。成功保存或明确取消后清除对应草稿。

草稿不是持久笔记，不跨插件重载、应用重启或普通关闭后重新打开保留。没有永久 ID 的高亮如果正文及位置同时发生变化，不承诺自动把草稿关联到新的提取结果。

## 验证

`npm run test:views` 覆盖：

1. A/B 文件返回顺序变化时，仅显示最后选择的页面。
2. 全局搜索期间切换笔记，不恢复旧文件。
3. `comment:` 刷新、切换及清空范围保持相同语义。
4. 进入 HiCard 后，旧高亮和旧授权结果不覆盖页面。
5. Canvas 和关闭页面后的异步结果被丢弃。
6. 桌面窄窗格导航、搜索范围操作、会话保存和分页重置。
7. 本地筛选不重复读取同一范围，评论更新不被旧搜索缓存覆盖。
8. 草稿挂起与恢复、保存后清除、搜索监听清理。
9. 跨文件搜索结果及晚到回复保留正确的评论来源。

这些测试直接运行当前控制器并使用模拟 DOM、可控异步请求，不等同于真实 Obsidian 或移动端的端到端验收。视觉布局与真实移动端操作仍需实机复核。
